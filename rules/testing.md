# Testing

Follow the project's documented test commands and required checks. Use regression tests for
bugs and behavior tests for new functionality. Choose unit, integration and browser tests
according to the change; browser tests are not required for a Python library.

Use tests first when useful or required by the project. Coverage thresholds come from project
policy. Report skipped tests, missing environments and checks not run. Never adjust a test
merely to hide a failure. Keep fixtures isolated from the user's real settings and services.
